# AI 게시글 작성 도우미 연동 컨텍스트

이 문서는 다음 작업 세션에서 프로젝트 구조와 AI 챗봇 연동 목표를 빠르게 파악하기 위한 인수인계 자료이다. 자동 적용되는 구현 지침이 아니며, 실제 작업 전에는 현재 브랜치와 작업 트리, 관련 `AGENTS.md`를 다시 확인해야 한다.

## 프로젝트 개요

이 프로젝트는 성균관대학교 구성원을 위한 분실물·습득물 플랫폼이다.

- 백엔드: FastAPI
- 프런트엔드: Expo 및 Expo Router
- AI 모듈: 텍스트 게시글 초안 생성, 사진 속성 추출, 모델 평가 도구
- 현재 구현: 인증, 게시글 CRUD, 사진 업로드, 게시글 추천 및 모바일 UI
- 현재 AI 상태: Streamlit 검증 코드를 기반으로 단일 요청 초안 생성 API와 Expo 초안 화면까지 1차 연결됨

## 주요 디렉터리

| 경로 | 역할 |
| --- | --- |
| `backend/app` | 인증, 사용자, 게시글, 카테고리 및 추천 API |
| `backend/app/integrations/ai` | OpenAI·Ollama provider, 텍스트 초안, 사진 분석, Streamlit 및 평가 harness |
| `backend/tests` | FastAPI 통합 테스트 |
| `frontend/src/app` | Expo Router 화면과 기존 2단계 게시글 작성 화면 |
| `frontend/src/lib` | 인증 및 게시글 API wrapper |

## 현재 작성 흐름

현재 프런트에는 AI 작성과 수동 작성을 선택하는 화면이 구현되어 있다.

1. 홈의 글쓰기 버튼에서 `LOST` 또는 `FOUND`를 선택한다.
2. `/create-post-method`에서 `AI와 함께 작성하기` 또는 `혼자 작성하기`를 선택한다.
3. `혼자 작성하기`는 기존 `/create-post` 2단계 작성 화면으로 이동한다.
4. 수동 작성 화면에서 카테고리, 시간, 장소, 특징, 제목, 설명과 사진을 입력한다.
5. 게시글을 먼저 생성한 뒤 사진을 별도 API로 차례대로 업로드한다.
6. 수동 게시글은 `creation_method=MANUAL`로 저장된다.

`AI와 함께 작성하기`는 현재 `/create-post-ai`로 이동한다. 사용자가 자연어 설명을 한 번 입력하면 인증된 `POST /api/v1/ai/post-drafts`를 호출하고, 반환된 제목, 설명, 카테고리, 장소와 시간을 초안 카드로 보여준다.

백엔드에는 사용자가 확인한 AI 초안을 저장하기 위한 `POST /api/v1/posts/ai-assisted`도 구현되어 있으며, 이 경로로 생성한 게시글은 `creation_method=AI_ASSISTED`로 저장된다. 다만 현재 AI 화면에는 이 저장 경로로 이어지는 최종 확인·게시 UI가 연결되어 있지 않다.

## 현재 구현 상태

| 기능 | 상태 | 비고 |
| --- | --- | --- |
| LOST·FOUND 작성 진입 | 구현 | 홈의 글쓰기 버튼에서 선택 |
| AI·수동 작성 방식 선택 | 구현 | `/create-post-method` |
| 수동 게시글 작성·수정 | 구현 | `/create-post` |
| 수동 사진 업로드 | 구현 | 게시글 생성 후 별도 업로드 |
| AI 자연어 초안 생성 | 구현 | 단일 요청 기반 `/create-post-ai` |
| 인증된 AI 초안 API | 구현 | `POST /api/v1/ai/post-drafts` |
| AI-assisted 게시글 저장 API | 구현 | `POST /api/v1/posts/ai-assisted` |
| AI 다중 대화와 추가 질문 | 미구현 | 현재는 설명 한 번당 초안 한 번 생성 |
| AI 화면 사진 첨부·분석 | 미구현 | Streamlit 사진 분석 코드는 있으나 서비스 미연결 |
| AI 미리보기·수정·게시 | 미구현 | 초안 카드 이후 흐름 연결 필요 |
| AI 초안의 기존 작성 폼 전달 | 미구현 | `/create-post` 재사용 연결 필요 |

## 이번 작업 목표

이미 구현된 작성 방식 선택과 단일 AI 초안 생성을 확장하여 다음 AI 작성 흐름을 완성한다.

1. AI 작성 채팅을 시작한다.
2. AI가 장소, 시간과 물품 특징 등 누락된 정보를 질문한다.
3. 사용자는 텍스트와 사진을 입력할 수 있다.
4. 사진에서 물품명, 카테고리, 색상, 재질, 브랜드와 형태 등의 속성을 추출한다.
5. 대화와 사진 분석 결과를 구조화된 게시글 초안으로 만든다.
6. 별도 미리보기 화면에서 결과를 확인한다.
7. 내용이 맞으면 바로 게시하고, 수정이 필요하면 기존 작성 폼을 AI 값으로 채워 연다.
8. 기존 `POST /api/v1/posts/ai-assisted`를 사용해 `creation_method=AI_ASSISTED`로 저장한다.

AI 요청이 실패해도 입력한 텍스트와 선택한 사진을 유지하고 수동 작성 화면으로 전환할 수 있어야 한다.

## 확정된 결정

- 일반 상담 챗봇이 아니라 게시글 작성을 완료하기 위한 전용 AI 에이전트로 구현한다.
- 실제 서비스 provider는 OpenAI만 사용한다.
- 기존 Ollama 및 모델 평가 코드는 삭제하지 않는다.
- 대화 기록은 작성 중 프런트엔드 메모리에만 유지하며 DB에 저장하지 않는다.
- 사진 분석을 첫 버전에 포함한다.
- AI 작성 완료 후 별도 미리보기 화면을 제공한다.
- 미리보기의 `게시`는 현재 내용으로 바로 등록한다.
- 미리보기의 `수정`은 기존 `/create-post` 폼을 재사용한다.
- 첫 버전에는 LangGraph를 사용하지 않고 명시적인 상태 흐름을 사용한다.

## 현재 API와 추가 작업

### 구현된 `POST /api/v1/ai/post-drafts`

- 인증 필수
- 게시글 유형, 자연어 설명과 선택적으로 사용자가 확정한 장소·시간을 입력받는다.
- 검증된 제목, 설명, 물품명, 카테고리, 장소, 시간, 키워드, 누락 필드와 경고를 반환한다.
- 요청 중 게시글이나 대화 내용을 저장하지 않는다.

### 구현된 `POST /api/v1/posts/ai-assisted`

- 인증 필수
- 사용자가 최종 확인한 게시글 데이터를 입력받는다.
- 기존 게시글 서비스를 사용하고 `creation_method=AI_ASSISTED`를 서버에서 지정한다.
- 기존 `POST /api/v1/posts`는 계속 `MANUAL` 게시글을 생성한다.

### 추가할 대화 API

- 기존 초안 API를 확장하거나 별도 채팅 API를 추가한다.
- 게시글 유형, 대화 내역, 현재 초안과 기준 시각을 입력받는다.
- AI의 다음 질문, 갱신된 초안, 누락 필드, 경고와 진행 상태를 반환한다.
- 진행 상태는 최소한 `NEEDS_INPUT`과 `READY`를 구분한다.

### 추가할 사진 분석 API

- 인증 필수
- JPEG, PNG 또는 WebP 사진 한 장을 입력받는다.
- 물품명, 카테고리, 색상, 재질, 브랜드, 형태, 특징과 경고를 반환한다.
- 분석 요청에 사용한 사진을 대화 기록이나 임시 게시글로 저장하지 않는다.

OpenAI API 키는 백엔드 환경 변수로만 관리하고 프런트엔드에 전달하지 않는다. 모델 출력은 JSON Schema와 Pydantic으로 다시 검증한다.

## 구현 시 주의사항

- 기존 AI 코드는 `core.*` 형태의 Streamlit 전용 import를 사용하므로 FastAPI 패키지 구조에 맞게 정리해야 한다.
- 현재 텍스트 프롬프트가 실제 앱에서 한국어 제목과 설명을 안정적으로 생성하는지 재검증하고 필요하면 수정한다.
- AI는 GPS 좌표나 확인되지 않은 장소, 시간, 브랜드와 특징을 만들어서는 안 된다.
- 모호하거나 누락된 정보는 추측하지 말고 사용자에게 추가 질문한다.
- 사용자 원문, 위치, 이메일, 사진, access token, API key와 모델 원문 응답을 로그에 남기지 않는다.
- timeout, rate limit, 5xx, 거부와 잘못된 모델 응답을 구분된 안전한 오류로 변환한다.
- 다른 팀원의 변경과 수정 중인 루트 `README.md`를 덮어쓰지 않는다.
- 백엔드, 프런트엔드와 AI 영역을 수정하기 전에 각 범위의 `AGENTS.md`를 읽는다.

## 테스트 목표

실제 OpenAI API에 의존하지 않는 Fake Provider 또는 mock 기반 자동 테스트를 우선 작성한다.

- 정상적인 다중 대화와 초안 완성
- 장소, 시간 또는 물품 정보가 누락된 경우의 추가 질문
- 사진 분석 결과가 초안에 병합되는 과정
- 인증되지 않은 AI API 요청 거부
- 잘못된 JSON, 누락 필드와 허용되지 않은 카테고리 거부
- timeout, 429, 5xx와 모델 거부 처리
- prompt injection 입력 처리
- 로그와 오류 응답에 개인정보 및 API key가 포함되지 않는지 확인
- 기존 AI-assisted 저장 API의 `AI_ASSISTED` 유지 확인
- 기존 수동 게시글의 `MANUAL` 유지 확인
- AI 실패 후 수동 작성으로 전환되는 프런트 흐름
- 프런트엔드 lint 및 TypeScript 검사
- 백엔드 전체 pytest

## 작업 전 확인 사항

- 이 문서는 구현 완료 보고서가 아니라 향후 작업을 위한 컨텍스트 문서이다.
- 실제 구현 전 최신 커밋, 현재 브랜치와 미커밋 변경을 다시 확인한다.
- API와 화면 구조는 최신 백엔드·프런트엔드 코드에 맞춰 재검증한다. 특히 이미 구현된 `/create-post-method`, `/create-post-ai`, `/api/v1/ai/post-drafts`와 `/api/v1/posts/ai-assisted`를 중복 구현하지 않는다.
- 기존 AI 평가 결과와 Streamlit 데모는 서비스 연동과 별도로 유지한다.

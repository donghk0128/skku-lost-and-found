# 1차 작업: 장소 사전 및 검색 로직 정비

## 요약

이번 작업은 `backend/app/ai/knowledge` 내부로 한정한다. 공식 성균관대학교 캠퍼스맵의 **건물과 편의시설**을 기준으로 양 캠퍼스 장소 사전을 확장하고, 같은 이름의 장소를 캠퍼스·입점 위치별로 구분하며, 한 문장에서 여러 장소를 검출하도록 테스트한다. 공용 API, 게시글 DB, 프런트는 변경하지 않는다.

## 구현 변경

- `campus_locations.json`에 공식 캠퍼스맵의 건물과 주요 랜드마크를 추가한다.
  - 인문사회과학캠퍼스: 정문·후문·금잔디광장, 600주년기념관, 법학관, 교수회관, 중앙학술정보관, 학생회관, 국제관, 퇴계인문관, 다산경제관, 경영관, 호암관, 수선관·별관, 기숙사와 전통 건축물 등.
  - 자연과학캠퍼스: 정문·북문·북서문·킹고광장·글로벌광장, 학생회관, 복지회관, 수성관, 제1·2공학관, 자연과학관, 화학관, 반도체관, 삼성학술정보관, 기초학문관, 약학관, 생명공학관, 의학관, N센터, 연구동과 기숙사 등.
- 캠퍼스맵의 `편의시설` 탭이 반환하는 항목도 장소 사전에 추가한다.
  - 화면 템플릿의 `buildSubList.bizNm`과 `buildSubList.bizNmEng`를 각각 공식 한글·영문 명칭으로 사용하고, 실제 목록을 채우는 네트워크 응답에서 캠퍼스, 소속 건물, 층·공간 코드와 좌표 등 제공되는 위치 정보를 함께 확인한다.
  - 식당, 카페, 편의점, 은행·ATM, 우체국, 복사실 등 시설 종류는 API 응답에 존재하는 공식 분류만 사용한다. 화면이나 응답에서 확인되지 않은 시설·분류는 추측해 추가하지 않는다.
  - 동일 브랜드나 동일 명칭이 여러 캠퍼스 또는 건물에 있으면 하나로 합치지 않고 입점 위치별 ID로 분리한다.
  - 폐점·이전 가능성이 있는 편의시설은 캠퍼스맵 응답에 현재 노출되는 항목만 등록하고 수집 기준일을 데이터 또는 README에 기록한다.
- 장소 항목은 `id`, `campus`, `building_number`, `names.ko/en`, `aliases.ko/en` 구조로 관리한다.
- 편의시설도 기존 장소 구조를 재사용한다. 시설 구분이 필요하면 각 항목에 선택 필드 `kind: "facility"`와 공식 분류 `category`만 추가하고 별도 사전이나 검색 로직은 만들지 않는다.
- 편의시설의 소속 건물을 확인할 수 있으면 `parent_location_id`로 기존 건물 항목을 참조한다. 층·공간 코드처럼 지점별 위치 정보는 공식 응답에 값이 있을 때만 보존한다.
- `student_center`처럼 양 캠퍼스에 존재하는 이름은 `hssc_student_center`, `nsc_student_center`처럼 별도 ID로 분리한다.
- 별칭은 공식 명칭과 분리한다. `중도`, `삼도`, `디도`, `학관`, `일공`, `이공`, `기학`, `생명공학관` 등은 실제 사용 여부를 개발자가 검토한 뒤 등록한다.
- 캠퍼스 단서가 있으면 해당 캠퍼스 장소를 우선한다.
  - `율전 학생회관` → 자연과학캠퍼스 학생회관
  - `명륜 학생회관` → 인문사회과학캠퍼스 학생회관
- 캠퍼스 단서 없이 공통 명칭만 입력하면 임의로 하나를 확정하지 않고 두 후보를 모두 반환한다.
- `find_locations()`는 등장 위치 순으로 복수 장소를 반환하도록 조정한다. 현재의 별칭 길이 기준 정렬은 사용자 문장 순서를 보존하지 않으므로 교체한다.
- 긴 명칭을 우선 매칭해 `수선관 별관`이 `수선관`과 중복 검출되지 않게 한다.
- `find_location()`은 정확히 한 후보일 때만 장소를 반환하는 기존 호환 동작을 유지한다.
- 층 정보 보존은 기존과 동일하게 유지하고 `B1`, `지하 1층`, `3층` 표기를 검증한다.

## 테스트

새 AI 전용 테스트에서 다음을 검증한다.

- 모든 장소 ID가 고유하고 `ko/en` 정식 명칭이 존재한다.
- 같은 장소 안에서 정규화된 별칭이 중복되지 않는다.
- 편의시설은 `bizNm`/`bizNmEng`의 공식 명칭으로 검색되며 결과가 소속 건물과 캠퍼스를 보존한다.
- 같은 이름의 편의시설이 여러 곳에 있으면 서로 다른 ID로 로드되고, 건물·캠퍼스 단서가 있을 때 해당 지점으로 해소된다.
- 위치 단서 없는 중복 편의시설명은 모든 후보를 반환하며 `find_location()`은 `None`을 반환한다.
- 편의시설의 `parent_location_id`는 실제 건물 ID만 참조한다.
- 캠퍼스별 동일 명칭이 서로 다른 ID로 로드된다.
- 한글·영문 정식 명칭 및 별칭을 모두 검색할 수 있다.
- `삼성학술정보관과 학생회관 사이`에서 두 장소가 문장 순서대로 검출된다.
- `수선관 별관`이 수선관과 중복되지 않는다.
- `율전 학생회관`과 `명륜 학생회관`이 각각 올바른 캠퍼스로 해소된다.
- 캠퍼스 단서 없는 `학생회관`은 복수 후보가 되어 `find_location()`이 `None`을 반환한다.
- 명시된 층 정보가 localized canonical name 뒤에 보존된다.
- 임의 문자열과 너무 짧은 별칭이 오탐되지 않는다.
- 기존 AI service와 workflow가 `find_locations()`의 복수 결과를 그대로 처리하는지 회귀 테스트한다.

## 작업 경계와 기준

- 공식 명칭, 건물 번호와 편의시설 입점 정보의 출처는 성균관대학교 [국문 캠퍼스맵](https://www.skku.edu/skku/about/campusInfo/campusMap.do)과 [영문 캠퍼스맵](https://www.skku.edu/eng/About/campusinfo/CampusMap.do)으로 고정한다. 편의시설은 개발자 도구 Network 탭에서 `편의시설` 선택 시 호출되는 응답과 화면의 `buildSubList.bizNm`/`bizNmEng` 바인딩을 대조해 확정한다.
- 공식 페이지에 없는 별명은 추측해서 추가하지 않고 개발자가 확인한 것만 등록한다.
- 이번 단계에서는 장소 선택 API, AI 응답 schema, 게시글 저장 구조와 프런트 버튼을 변경하지 않는다.
- README의 장소 사전 구조와 캠퍼스 중복 명칭 처리 설명만 실제 구현에 맞춰 갱신한다.
